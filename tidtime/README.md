# ติดทาม 0.1.1

แอป Windows x64 สำหรับเจ้าหน้าที่ตรวจข้อมูลแปลงเดียวจากสองรอบสำรวจ ใช้ ExcelJS อ่านไฟล์ในเครื่อง และเก็บสำเนาค่าที่อ่านพร้อมประวัติผลตรวจเป็น JSON ใน `%APPDATA%\tidtime\surveys` ไฟล์ต้นทางยังอยู่ที่เดิม เปิดงานที่บันทึกแล้วได้แม้ย้ายไฟล์ Excel ไปแล้ว

## เปิดแอป

จากโฟลเดอร์หลักของ repository เปิด Terminal แบบ PowerShell ใน VS Code แล้วพิมพ์

```powershell
cd .\tidtime
npm.cmd ci
npm.cmd run samples
npm.cmd start
```

เครื่องพัฒนาต้องมี Node.js และ npm (ทดสอบกับ Node.js 26) การติดตั้ง dependency และสร้างตัวติดตั้งครั้งแรกใช้อินเทอร์เน็ต เมื่อเตรียมเสร็จแล้วใช้แอปสำรวจแบบออฟไลน์ได้ เครื่องที่ใช้ตัวติดตั้งไม่ต้องติดตั้ง Node.js

## ลองตรวจหนึ่งงาน

1. ในหน้านำเข้า เลือก `examples\P01-2568.xlsx` เป็นรอบก่อน และ `examples\P01-2569.xlsx` เป็นรอบปัจจุบัน เลือกชีต **สำรวจ** ทั้งคู่ ตรวจว่าเป็น P01 ปี 2568 กับ 2569 ฝั่งละ 5 แถว แล้วกด **เริ่มเปรียบเทียบ**
2. เลือกลำดับ 1 จะเห็นความสูงลดลง 0.5 เมตร จาก 1.5 เป็น 1 พร้อมหลักฐานสองฝั่ง ลำดับ 3 มีเฉพาะคำเตือน RCD ลดลง 0.25 ซม. ส่วนลำดับ 4 ความสูงว่างแต่ตรวจ RCD ได้
3. เลือกลำดับ 2 จะเห็น T002 มะขามป้อม และ T019 หว้า พร้อมสถานะรอตรวจตัวต้น เลือก **ยืนยันว่าปลูกทดแทน** ระบุวันที่ตรวจและหมายเหตุ “เจ้าหน้าที่ประจำแปลงยืนยันทางโทรศัพท์” ถ้าทราบวันที่ปลูกจริงให้กรอกแยก แล้วกด **บันทึกผลตรวจ** จะเห็นความสูงแรกของหว้า 0.7 เมตร
4. ปิดแอป เปิดใหม่ แล้วกด **งานที่บันทึก** เลือกงานและจุดเดิม ดูประวัติท้ายหน้าจอ การแก้ผลแล้วบันทึกเพิ่มจะสร้างประวัติอีกครั้ง คงรายการเก่าไว้ หากต้องการทดสอบกติกาอีกทาง ให้เปลี่ยนผลเป็น **ยืนยันว่าเป็นต้นเดิม** โปรแกรมจึงตรวจการลดลงระหว่างสองแถวนั้น
5. เริ่มงานอีกครั้งโดยเลือกชีต **ทดสอบคีย์ซ้ำ** ของปี 2569 ลำดับ 1 มีสองแถวในรอบใหม่ (3 และ 7) และแถว 8 ขาดลำดับ ดูหลักฐานแต่ละแถวได้ ทั้งสองกรณีพักการคำนวณ

สำหรับชีตรูปแบบตัวอย่าง หัวตารางต้องอยู่แถว 1 ใช้ชื่อในไฟล์ตัวอย่าง คอลัมน์หมายเหตุตัดออกได้ ช่องวันที่สำรวจเว้นว่างได้ เมื่อทุกแถวของแต่ละรอบมีวันที่สำรวจวันเดียวกัน แอปเรียงรอบตามวันที่จริง จึงเทียบมกราคมกับมิถุนายนในปีเดียวกันได้ หากวันที่ไม่เพียงพอ แอปใช้ปีรอบสำหรับรอบที่อยู่คนละปี สำหรับรอบถัดไป ให้นำไฟล์ที่มีค่าครั้งแรกของต้นใหม่มาเป็นรอบก่อน เมื่อตรวจจุดเดิมจะเทียบกับต้นใหม่ งานเดิมเก็บหลักฐานก่อนทดแทนและเลขแถวฐานของต้นใหม่ไว้ทั้งคู่

## เทียบ MRIS กับแบบฟอร์มภาคสนาม

เลือกรอบก่อนเป็นไฟล์ Snapshot แล้วเลือกชุด **รหัสแปลง · รวมกลุ่มไม้ป่าและไม้ผล · วันที่วัด** แอปจะอ่านตาราง growth_forest, growth_rubber, growth_bamboo, growth_fruit และ growth_banana ที่มีอยู่ เชื่อมทะเบียน trees และ tree_subtypes ด้วย UUID ในไฟล์ แยกชุดตามแปลงและวันที่วัด คำว่า «รวม» ครอบคลุมห้ากลุ่มนี้

เลือกรอบปัจจุบันเป็นแบบฟอร์มภาคสนาม แล้วเลือก **ทั้งแปลง · รวมชีตไม้ป่าและไม้ผล** เพื่อให้พบต้นที่เปลี่ยนหมวดข้ามชีต ระบุปีรอบตามทะเบียน เช่น 2568 และ 2569 ค่าวันที่สำรวจยังมาจากไฟล์แต่ละฝั่ง เลือกเฉพาะกลุ่มได้เมื่อใช้กลุ่มเดียวกันทั้งคู่

MRIS ไม่มีคอลัมน์ลำดับต้นในทะเบียน รูปแบบรหัสที่รองรับ เช่น P99A01987 มีลำดับ 987 ในสามหลักท้าย แอปตรวจรหัสแปลงกับรูปแบบรหัสเต็มก่อนใช้ลำดับ ถ้าอ่านลำดับไม่ได้หรือพบคีย์ซ้ำจะพักจุดนั้น ในรายละเอียดดูชีตและเลขแถวของการวัด กับแถวของทะเบียนที่ใช้เชื่อมได้

## ตามโค้ด

- `mris.js` อ่านความสัมพันธ์ระหว่างตารางใน Snapshot แล้วส่งแต่ละจุดเข้า `pairRounds` เช่นเดียวกับข้อมูลแบบฟอร์ม

- `excel.js` จับคู่ชื่อหัวตารางกับชื่อฟิลด์ใน JavaScript อ่านค่าโดยเก็บเลขแถว Excel และตรวจข้อมูลระดับชีต
- `compare.js` เริ่มอ่านจาก `pairRounds` ซึ่งรวบรวมทุกแถวไว้ตามแปลงและลำดับต้น แล้วอ่าน `compareTree` ซึ่งรับหนึ่งจุดกับผลตรวจล่าสุด คืนสถานะ รายการข้อสังเกต และตัวบอกว่าต้องตรวจต่อหรือไม่ กติกาคำนวณใช้เลขฐานสิบเพื่อเก็บผลต่างอย่าง 0.25 ซม.
- `store.js` เก็บข้อมูลสองรอบไว้กับงาน ทุกครั้งที่บันทึกจะเพิ่มเหตุการณ์ในประวัติ แล้วเขียนไฟล์ชั่วคราวก่อนเปลี่ยนชื่อเป็นไฟล์งาน
- `main.js` ทำงานฝั่ง Electron ที่เปิดไฟล์และเรียกคลังข้อมูล `preload.js` เปิดเฉพาะคำสั่งที่หน้าจอเรียกได้
- `index.html` และ `renderer.js` เก็บข้อความและขั้นตอนบนหน้าจอ ส่วน `style.css` กำหนดหน้าตา ข้อความผลคำนวณอยู่ใน `compare.js`
- ตัวอย่างฝึกเดิมที่ใช้ console.log อยู่ใน `../learn/compare-demo.js`

## ทดสอบและสร้างตัวติดตั้ง

รันจากโฟลเดอร์เดียวกับ package.json

```powershell
npm.cmd test
npm.cmd run test:ui
npm.cmd run dist:win
```

ชุดทดสอบสร้าง Excel สมมติในโฟลเดอร์ชั่วคราวเอง ชุดแรกอ่าน Excelและตรวจผลเปรียบเทียบกับประวัติ ชุด UI เปิด Electron สองครั้ง โดยใช้โฟลเดอร์ข้อมูลชั่วคราวและส่งไฟล์ตัวอย่างแทนกล่องเลือกไฟล์ของ Windows ตัวติดตั้งอยู่ที่ `dist\tidtime-Setup-0.1.1-x64.exe` รุ่นทดลองนี้ยังไม่ได้ลงลายเซ็นดิจิทัล

สร้างไฟล์ตัวอย่างใหม่ได้ด้วย `npm.cmd run samples` คำสั่งนี้เขียนทับไฟล์ตัวอย่างสองไฟล์ใน examples
